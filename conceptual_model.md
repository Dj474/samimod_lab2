# Концептуальная модель грузового аэропорта (вариант №15)

## 1. Объект моделирования

Грузовой аэропорт. В аэропорт прибывают грузы в контейнерах. Самолёты
отправляются в рейс после полной загрузки. Используются два типа самолётов:

- обычной грузоподъёмности (`C_n`);
- повышенной грузоподъёмности (`C_h > C_n`).

Управляющий старается как можно чаще использовать самолёты обычной
грузоподъёмности: самолёты повышенной грузоподъёмности используются только
при отсутствии на аэродроме свободных обычных самолётов.

## 2. Цель моделирования

Оценить характеристики функционирования аэропорта при различных параметрах
входного потока, а именно:

1. число вылетевших рейсов за горизонт;
2. долю рейсов, выполненных самолётами повышенной грузоподъёмности;
3. среднее число контейнеров в накопителе (складе);
4. среднее время ожидания контейнера на складе до загрузки.

## 3. Границы системы и основные допущения

- Грузопоток — пуассоновский (интервалы между поступлениями контейнеров
  распределены экспоненциально с интенсивностью λ).
- Вес каждого контейнера — случайная величина, равномерно распределённая на
  интервале [W_min; W_max], тонны.
- Самолёт отправляется в рейс **только после полной загрузки**: загрузка
  продолжается, пока суммарный вес загруженных контейнеров не достигнет
  грузоподъёмности самолёта (последний контейнер может превысить
  грузоподъёмность — перегруз считается допустимым).
- Контейнеры снимаются со склада в порядке FIFO.
- Время загрузки одного контейнера — экспоненциальное со средним `t_load`.
- После вылета самолёт находится в рейсе (включая разгрузку и возврат)
  экспоненциальное время со средним `t_flight`, после чего снова готов к
  загрузке на аэродроме.
- Количество самолётов каждого типа задано (`n_normal`, `n_high`).
- Вместимость склада не ограничена.
- Число одновременно выполняемых загрузок не ограничено (один самолёт на
  стоянке, загрузка независима).
- Горизонт моделирования конечный, `T` часов.

## 4. Элементы модели (объекты)

| Элемент | Описание | Характеристики |
|---|---|---|
| **Контейнер** | единица груза, поступающая на склад | автоматически получает вес `W ~ U(W_min, W_max)` и время поступления |
| **Склад (накопитель)** | хранилище невывезенных контейнеров | FIFO-очередь, учёт суммарного веса |
| **Самолёт обычной грузоподъёмности** | транспортное средство | грузоподъёмность `C_n`, в количестве `n_normal`, состояния: ГОТОВ / ЗАГРУЗКА / РЕЙС |
| **Самолёт повышенной грузоподъёмности** | транспортное средство | грузоподъёмность `C_h`, в количестве `n_high`, состояния: ГОТОВ / ЗАГРУЗКА / РЕЙС |
| **Диспетчер (управляющий)** | логика назначения самолётов | правило приоритета обычных самолётов |

**Правило диспетчера.** При каждом изменении состояния системы (поступление
контейнера, освобождение самолёта, завершение загрузки) предпринимается
попытка назначить самолёт:

1. если на складе накоплено не менее `C_n` тонн **и есть хотя бы один**
   свободный обычный самолёт — назначается обычный самолёт;
2. иначе (свободных обычных нет), если на складе накоплено не менее `C_h`
   тонн и есть свободный самолёт повышенной грузоподъёмности — назначается
   самолёт повышенной грузоподъёмности;
3. в противном случае назначение не происходит (самолёты ждут, накапливая
   груз).

## 5. Список событий (единственный механизм продвижения времени)

| Событие | Условие | Действия |
|---|---|---|
| `ARRIVAL` | генерация контейнера | добавить на склад, запланировать следующий `ARRIVAL`, запустить продвижение загрузки, попытка назначения |
| `LOAD_STEP` | загрузка контейнера на самолёт | снять контейнер со склада (FIFO), учесть вес, зафиксировать время ожидания; если самолёт загружен — событие отправки; иначе ожидание следующего контейнера |
| `DEPARTURE` | самолёт загружен | зафиксировать вылет (число рейсов, тип), перевести самолёт в состояние РЕЙС, запланировать `RETURN`, попытка назначения |
| `RETURN` | окончание рейса | перевести самолёт в состояние ГОТОВ, попытка назначения |
| `END` | `t = T` | остановка прогона, сбор статистики |

Продвижение времени — **по ближайшему событию** (next-event), постоянный шаг
отсутствует. В начале каждого прогона все самолёты ГОТОВЫ, склад пуст.

## 6. Случайные величины и генератор

Все случайные величины моделируются **единственным** встроенным датчиком
псевдослучайных чисел `random.Random(seed)` стандартного модуля `random`:

- интервал поступлений: `-ln(u)/λ`;
- вес контейнера: `W_min + u·(W_max − W_min)`;
- время загрузки контейнера: `-t_load·ln(u)`;
- время полёта: `-t_flight·ln(u)`.

Начальные номера прогонов (`seed = 1…N`) различаются, что обеспечивает
независимость повторных прогонов.

## 7. Отклики модели

| № | Отклик | Тип | Формула |
|---|---|---|---|
| R1 | число вылетевших рейсов `N_dep` | **аддитивный** | счётчик |
| R2 | доля рейсов повышенной грузоподъёмности `p_h` | **аддитивный** | `N_dep_h / N_dep` |
| R3 | среднее число контейнеров на складе (в среднем по времени) `Q` | **непрерывное** | `∫Q(t)dt / T` |
| R4 | среднее время ожидания контейнера на складе `W` | **дискретное** | `Σ w_i / N_loaded` |

Дополнительно фиксируются: суммарный вес вывезенного груза, остаток склада на
момент останова — для внутренней проверки баланса «прибыло = вывезено +
остаток».

## 8. Верификация модели

- **Внутренний баланс:** суммарный вес прибывших контейнеров = суммарный вес
  вывезенных грузов + суммарный вес контейнеров, оставшихся на складе.
- **Повторные прогоны:** `N = 100` независимых прогонов с разными seed; для
  каждого отклика вычисляются выборочное среднее, СКО, минимальное и
  максимальное значения, 95%-е доверительные интервалы (t-распределение).
- **Сходимость:** анализ графика скользящего среднего откликов по числу
  прогонов (стабилизация оценок).
- **Режим трассировки:** пошаговый протокол событий с указанием активного
  объекта (`CONTAINER_FLOW`, `PLANE_i`, `DISPATCHER`) для проверки корректности
  логики назначения самолётов.

## 9. Исходные данные

Исходные данные задаются в файле `config.json` (интенсивность поступлений,
характеристики веса контейнеров, число и грузоподъёмность самолётов, времена
загрузки и полёта, горизонт моделирования, число прогонов, режим трассировки).
